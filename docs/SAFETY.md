# 安全设计与合规边界 (Safety & Compliance)

`iPhone Duo Launch Assistant` 将“安全性”置于所有功能之上。本项目旨在为个人用户在首发场景提供透明、安全、可控的购买辅助，**坚决抵制黑产黄牛行为，不采用任何对抗风控或侵入式外挂技术**。

---

## 1. 核心安全铁律 (Absolute Prohibitions)

系统在架构与代码实现层面严格遵循以下铁律：

| 序号 | 规则 | 实现与约束机制 |
| :--- | :--- | :--- |
| **1** | **零密码与凭据托管** | 系统严禁以任何明文、加密形式保存用户的 Apple ID 密码。登录与二次验证完全由用户在原生 Chromium 窗口手动完成。 |
| **2** | **不绕过 2FA 双重认证** | 遇到 Apple ID 两步验证或短信/设备验证码时，系统主动进入等待状态，由用户本人完成手机端授权。 |
| **3** | **不破解 CAPTCHA 验证码** | 系统不内置任何验证码破解或代答服务。若遇到人机验证，立即触发声光告警提示人工接管。 |
| **4** | **低频合规与防滥用 (RateGuard)** | 严格限制轮询频次。线上轮询保持 20~30 秒并叠加随机抖动；线下自提监控实施单店强制 $\ge 2.0$ 秒休眠节流。 |
| **5** | **多级指数退避机制** | 捕获到 HTTP 403、429 或 541 边缘拦截响应时，自动触发 60s $\to$ 120s $\to$ 240s 阶梯退避并自动重置会话，杜绝雪崩效应。 |
| **6** | **零自动支付与终极下单停机** | 系统绝不代理支付操作。在到达支付方式选择或订单确认页时，强制移交焦点并交由用户本人核实支付。 |
| **7** | **严格会话 Fail-Closed 机制** | 开售前必须通过会话有效性检查。若会话失效，系统坚决拒绝静默降级为未登录状态，立即亮红熔断，防止非预期失败。 |

## 2. 规格防错：终极规格核验硬门禁 (`FINAL_TARGET_CHECK`)

在首发秒级响应过程中，为坚决杜绝因官方前端改版、DOM 抖动或网络延迟导致的“买错机型”、“买错容量”事故，系统在点击“添加到购物袋”的前一毫秒设立了**原子级终极硬门禁**：

```python
# 核心逻辑示意 (位于 src/apple_store.py)
if not (color_verified and storage_verified and catalog_sku_verified):
    logger.critical("🛑 [FINAL_TARGET_CHECK_FAILED] 规格核验未通过，坚决拒绝加车！")
    raise TargetSpecificationMismatchError("终极核验未通过，系统紧急熔断以防下错订单。")
```

- **外观颜色核验**：确保当前页面选中的颜色与目标配置（如星光白色）完全一致；
- **存储容量核验**：确保当前选中的容量规格（如 512GB）完全一致；
- **权威 Part Number 校验**：要求当前配置的官方 Part Number 与 Catalog 解析出的权威代码（如 `MK2P4CH/A`）完全一致；
- **单项失败即熔断**：任何一项不匹配，流程立即终止，绝不盲目提交。

## 3. 本地化与隐私保护

1. **会话与缓存完全本地化**：
   - 浏览器 Profile 持久化数据默认保存在本地 `./browser_data` 目录；
   - 官方 Catalog 缓存与状态文件均位于本地 `./cache` 与 `./state`；
   - 本地所有数据均在 `.gitignore` 保护列表中，绝不提交至任何公开仓库。
2. **凭据脱敏保护**：
   - 日志与控制中心界面中涉及的所有敏感字段（如飞书 Webhook）均实施自动化掩码脱敏处理（例如显示为 `https://open.feishu.cn/.../f1****4f`）。
3. **无外联遥测**：
   - 整个项目没有任何第三方数据打点、遥测上报或外部统计模块，仅通过用户自己配置的私有飞书群机器人或本地扬声器接收通知。
